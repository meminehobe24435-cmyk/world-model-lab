# 设计说明

本文说明 `world-model-lab` 的**建模选择与取舍**，以及每个选择的代价。

---

## 1. 任务定义

- **场景**：1m × 1m 桌面，4 个可推动长方体（1 个红色目标方块 + 3 个干扰方块），
  1 个绿色目标区，1 道遮挡墙。
- **动作**：末端执行器在桌面平面内的二维位移 `(dx, dy) ∈ [-1, 1]²`，
  单步位移上限 `MAX_STEP = 0.038 m`。
- **目标**：把红色方块推入目标区。
- **回合长度**：64 步；成功或目标方块掉下桌即终止。

### 为什么是"推动"而不是抓取
推动的接触几何简单（圆盘 vs AABB），可以做成**完全确定性**的准静态解算，
从而保证反事实配对的前缀逐像素一致。抓取会引入接触点选择、力闭合等一堆
非确定性来源，对一个"评测世界模型"的项目来说不划算。

---

## 2. 物理：准静态 position-based

`PushPhysics.step(action)` 的顺序：

1. 执行器按动作移动，并**夹在桌面内**；
2. 与执行器圆盘重叠的方块，沿"远离执行器"的方向推出（分离深度 = 重叠量）；
3. 方块之间做 8 轮等质量分离迭代，直到收敛；
4. 越出桌沿的方块记 `off_table` 事件并从后续交互中移除。

**接触强度**定义为该步方块的位移量，作为接触事件的强度标签。

### 一个反直觉的几何事实
执行器被夹在桌内，所以它**无法把方块完全推下桌** —— 刚好推到
`box.cx == -box.hx` 这个临界点就停了。掉桌实际由**方块之间的挤压**造成。
这条已经写成断言（`test_effector_cannot_push_box_fully_off_table`），
免得以后有人"修"错方向。

### 取舍
- ❌ 没有转动、没有摩擦锥、没有连续碰撞检测、没有堆叠。
- ✅ 完全确定、纯 numpy、GT 精确、CPU 上每秒可跑几百步。

---

## 3. 渲染：numpy 软件光栅化

世界三角形 → 视图变换 → 透视投影 → 屏幕空间三角形 → z-buffer 光栅化。
深度按 `1/z` 在屏幕空间线性插值（透视正确），逐像素做深度测试。
着色为逐面 Lambert 漫反射 + 环境光。

输出四路：
| 输出 | 用途 |
| --- | --- |
| RGB | 主视觉观测 |
| 深度（相机空间 z） | 空间一致性评测；反投影成点云 |
| 语义 id | 多模态输入的 one-hot 通道；失败模式分析 |
| 点云（反投影） | 3D 一致性 |

### 遮挡怎么变成可测量的量
`render(compute_visibility=True)` 会**再渲一遍"去掉遮挡墙"的场景**，
两次语义图中该方块的像素计数之比就是它的**可见比例**：

```
visibility(b) = |{pixels: sem_full == b.id}| / |{pixels: sem_nowall == b.id}|
```

遮挡墙后面的方块可见比例可以是 **0.0** —— 也就是在观测里**彻底消失**，
但物理上仍然存在、仍然可以被推动。这让"物体持久性"从一句口号变成一个
可以分桶统计的数字：`occluded_err / visible_err`。

这个做法比"用 z-buffer 判断"更直接也更准确，代价是每帧多渲一遍（可关闭）。

## 4. 数据

三类策略 + 一类配对：

| 来源 | 占比 | 作用 |
| --- | --- | --- |
| `expert` | ~52% | 脚本专家（先绕到方块背后站位，再沿"方块→目标区"推），成功率约 50% |
| `random` | ~24% | 随机动作，几乎全失败，提供低回报分布与"乱动"数据 |
| `perturb` | ~19% | 专家轨迹 + 周期动作扰动（模拟打滑、误触） |
| `counterfactual` | 160 对 | **前缀逐像素一致、后缀动作不同**的成对分支 |

### 反事实配对为什么是关键
它是"动作可控性"评测的数据基础。做法：

```
reset(seed) → 跑 k 步专家动作 → snapshot()
                                   ├── 支路 A：继续原动作 m 步
                                   └── 支路 B：从同一 snapshot 出发，动作加扰动 m 步
```

两条支路的**前 k 帧观测逐像素相同**（`test_counterfactual_prefix_identical` 锁死这条），
所以未来的任何差异都**只能归因于动作差异**。这是因果对照，不是相关性观察。

## 5. 模型

### 5.1 编码器（表示学习）
3×(Conv2d 4x4 s2) + 1×(Conv2d 3x3 s1)，输出 6×6×96 特征 → 128 维 → `mu/logvar`。

两种潜在表示：
- **连续 VAE**：`z = mu + sigma * eps`（训练时采样，推理时取均值），KL 项权重 `kl_beta=1e-3`。
- **离散 VQ 码本**：64 个码字，直通估计，损失 = 承诺损失 + 码本损失。这一支对应
  "tokenizer / VQ-VAE" 口径，用于消融"离散 token 是否更适合世界模型"。

### 5.2 动力学（核心）
动作条件**因果** Transformer：`token_t = [z_t ; a_t ; proprio_t ; lang]`，
输出 `ẑ_{t+1}`。

- 因果掩码由 `test_transformer_dynamics_is_causal` 锁定：改变 t 之后的动作
  **不能**影响 t 的输出，但**必须**影响 t 之后。
- GRU 变体用于消融，回答"序列建模能力到底来自 Transformer 还是只来自循环结构"。

### 5.3 潜空间 rollout
`WorldModel.rollout(z0, actions, proprio, lang)` 逐步自回归：每步只用**自己上一步
预测出的 z**，不读任何真实未来帧。这是"想象"与"重建"的分界线。

### 5.4 多任务头
| 头 | 输出 | 对应 JD |
| --- | --- | --- |
| 解码器 | RGB / 深度 / 语义 | action-conditioned video prediction |
| 状态头 | 每方块 9 维 `(cx,cy,z,hx,hy,hz,vx,vy,alive)` | 动力学准确性、3D 状态 |
| 事件头 | 接触 / 掉桌（2N+1 维，BCE） | 接触事件预测 |
| 任务头 | 目标距离 / 成功 / 终止 / 存活 | 奖励、成功概率、终止状态 |

### 5.5 损失
```
2.0·L1(RGB) + 1.0·L1(depth) + 1.0·CE(semantic)
+ 1.0·MSE(ẑ_{t+1}, z_{t+1})      # 潜动力学
+ 1.0·MSE(state) + 0.5·BCE(event) + 0.5·MSE(task)
+ 1e-3·KL                        # 或 VQ 承诺损失
```
潜动力学目标用 `z.detach()`，避免"把编码器拉塌来降低预测误差"这种退化解。

## 6. 下游任务：潜空间 MPC

`receding horizon` 闭环：

1. 当前真实观测 → `z0`
2. 采样 N 条候选动作序列（长度 H），按 `MAX_STEP` 累积执行器位置构造本体状态
3. 在世界模型里 rollout，用任务头预测的 `-目标距离 + 0.5·成功概率`（按步加权）打分
4. CEM 迭代：取精英样本收紧分布，重复 `n_rounds` 轮
5. 只把最优序列的**第一个动作**施加到真实环境，回到 1

**注意**：规划器**不读特权物理** —— 本体状态里的执行器位置是按动作累积算出来的近似
（忽略桌边裁剪）。这是刻意的：让"下游收益"反映世界模型本身的质量，
而不是偷偷用了 GT。

---

## 7. 已知限制（写清楚，不藏）

1. **物理是简化的**：平面推动，无转动/堆叠/摩擦锥。
2. **规模小**：48×48、4 物体、CPU 训练。结论只在本场景内成立。
3. **不是任何论文的复现**：Dreamer / TD-MPC / V-JEPA / Genie 是相关工作，不是复刻对象。
4. **无 diffusion / flow matching**：图像走 VAE/VQ + 反卷积解码。
5. **语言是模板短句**：字符级嵌入 + 平均池化，不是 LLM 指令理解。
6. **规划器用近似本体状态**：执行器位置按动作累积，忽略桌边裁剪。
7. **评测集规模有限**：默认 val/hard 各 23 条轨迹、反事实 160 对、
   MPC 16 个布局 —— 足够看趋势，不足以给置信区间。
