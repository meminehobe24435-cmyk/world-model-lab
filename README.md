# world-model-lab

**动作条件潜在动力学世界模型：在可交互 3D 场景上训练、并按"动作可控性"等维度做系统评测的最小可复现实现。**

纯 numpy + PyTorch，无 GPU、无 MuJoCo/Isaac、无外部资产。`make test` 一条命令跑完全部单元测试。

```
场景（自带渲染器）           世界模型                                   评测
┌──────────────────┐   ┌──────────────────────────────────┐   ┌──────────────────────┐
│ 桌面推动任务      │   │ Encoder  CNN -> z_t              │   │ 动作可控性（反事实）  │
│ 4 个方块 + 遮挡墙 │   │   ├ 连续 VAE（mu/logvar + KL）    │   │ 动力学准确性 ADE/FDE  │
│ 绿色目标区        │──▶│   └ 离散 VQ 码本（tokenizer）     │──▶│ 空间一致性 / IoU      │
│ RGB 深度 语义 点云│   │ Dynamics 动作条件 Transformer     │   │ 长期预测误差曲线      │
│ 语言指令 本体状态 │   │   （GRU 变体用于消融）            │   │ 物体持久性（遮挡分段）│
│ 完整 GT：位置/接触│   │ Decoder  -> RGB 深度 语义         │   │ 泛化（留出/困难布局） │
│ 事件/成功/遮挡比例│   │ Heads    -> 状态 事件 奖励/成功   │   │ 下游收益（潜空间 MPC）│
└──────────────────┘   └──────────────────────────────────┘   └──────────────────────┘
```

## 1. 这个项目在做什么

给定一段**观测历史**和一个**未来的动作序列**，预测未来的观测、物体状态、接触事件与任务结局。

任务设定：桌面上有若干个方块，其中一个红色方块是目标物体，要把**推动**它进入绿色目标区。
动作是末端执行器在桌面平面内的二维位移。场景里有一道**遮挡墙** —— 墙后面的方块在图像里
**完全不可见**（可见像素为 0），但物理上仍然存在并且可以被推动。这一条是刻意的：
它让"物体持久性"和"长时序记忆"变成**可测量的量**，而不是口号。

模型必须在**潜空间里自回归**地往前推演：第 t 步的预测只能看到第 0 帧的真实观测和自己
前面预测出来的潜在，**不能读任何真实未来帧**。这是判断一个 world model 是否真的在
"想象未来"、还是只是在做逐帧重建的分界线。

### 明确不做的事（先划清边界）

- **不是完整刚体物理**。物体运动限制在水平面内（推动任务），高度只用于渲染排序与遮挡；
  没有转动惯量、没有摩擦锥、没有连续碰撞检测。这是一个**简化但确定性**的交互场景。
- **不是视频生成模型**。没有 diffusion / flow matching；图像重建走的是 VAE/VQ + 反卷积解码。
- **不是任何论文的复现**。Dreamer / TD-MPC / V-JEPA / Genie 等是**相关工作**，本项目没有复刻
  它们的算法与实验设置，请勿按"复现"理解。
- **语言指令是模板生成的短句**，用字符级词表 + 嵌入做条件，不是 LLM 指令理解。
- **规模小**。48×48 观测、4 个物体、CPU 可训练。所有结论只在**本项目的场景内**成立。

## 2. 快速开始

```bash
pip install -r requirements.txt

make test      # 单元测试（含物理方向回归、因果性、反事实前缀一致性）
make smoke     # 渲染 + 物理自检，几十秒，不需要数据集
make data      # 采集数据集（CPU 约 3-5 分钟）
make train     # 训练主模型
make bench     # 完整评测 -> runs/base/benchmark_val.json
make ablation  # 三个消融：无动作条件 / GRU 动力学 / VQ tokenizer
```

Windows 上没有 make 就直接照抄 `Makefile` 里对应的 python 命令，每条都独立可跑。

单步命令：

```bash
python scripts/collect_all.py --out data --scale 1.0
python -m wm.train --data data --out runs --name base --epochs 12
python -m wm.bench.run_benchmark --ckpt runs/base/ckpt.pt --data data --out runs/base --tag val
```

## 3. 评测维度

| 维度 | 指标 | 怎么算 |
| --- | --- | --- |
| **动作可控性** | `divergence_corr`、`action_sensitivity` | **反事实配对**：两条支路观测前缀逐像素一致，只有动作不同。把同一帧编码成 z0，分别用两条动作后缀 rollout，比较"预测分歧"与"真值分歧"的相关性；`action_sensitivity` = 预测分歧 / 零动作基线分歧，用来抓"不管给什么动作都预测同一件事"的退化模型 |
| **动力学准确性** | `ade` / `fde` / `err_curve` | 状态头预测的方块中心位置 vs 真值（米） |
| **空间一致性** | `depth_mae` / `occupancy_iou` | 解码深度 vs 真值深度的 MAE 与占据 IoU |
| **长期预测** | `pos_err_t1…t16`、`degradation_ratio` | 误差随步长的曲线与 16 步 / 1 步的退化比 |
| **物体持久性** | `occlusion_penalty` | 误差按"目标当帧是否被遮挡"分段；比值越接近 1 说明模型越能靠记忆维持不可见物体 |
| **泛化** | val / hard 两套留出布局 | hard 布局的目标区被刻意放到更远处 |
| **失败模式** | `contact_err` / `no_contact_err` / `occluded_err` | 按是否有接触、是否被遮挡分桶 |
| **下游收益** | MPC 成功率 vs 随机 vs 脚本专家 | 用世界模型在潜空间做 CEM 规划，**闭环**执行（receding horizon），只把规划的第一步施加到真实环境 |

## 4. 结果

完整分析与原始数字见 **[`docs/benchmark.md`](docs/benchmark.md)**。摘要：

| 维度 | 结果 | 判断 |
| --- | --- | --- |
| 重建 / 空间一致性 | 深度 MAE **0.0070**、占据 IoU **0.987** | ✅ 很好 |
| **动作可控性** | 预测分歧/真值分歧 = **0.963**，相关性 **+0.38** | ✅ 敏感度标定准确 |
| 物体持久性 | 被遮挡物体误差仅高 **1.32×**（遮挡时可见像素为 0） | ✅ 潜在维持了不可见物体 |
| 长时序退化 | t16/t1 = **1.24×** | ✅ 曲线平滑 |
| **动力学准确性** | `ade` 0.204 m，**但 `err_t0`（表征天花板）已是 0.184 m** | ⚠️ 瓶颈是跨布局泛化，不是动力学 |
| 任务头 | `dist_corr` = **−0.16** | ❌ 基本没学会 |
| **下游 MPC** | **0% vs 随机 0% vs 脚本专家 31%** | ❌ **负结果**，见下文 |

**三项消融都跑出了典型的世界模型退化模式**（详见 `docs/benchmark.md` §4）：

- `gru` 变体：给任何动作都预测同一个潜在，`sensitivity_ratio` 掉到 **0.004** —— 忽略动作。
- `no_action` 变体：`ade` 反而更低（0.184 < 0.204）却过度敏感（2.09）——
  **说明单看预测误差会骗人，动作可控性必须单列指标**。
- `vq` 变体：码本坍缩，`dyn` 损失低到 0.0004"看起来完美"，
  但真值潜在的分歧已经变成 **0.0**，表征死了。

**负结果如实写出来**：潜空间 MPC 没能跑赢随机动作。诊断是
规划器的打分函数（任务头）本身没有信息量（`dist_corr = −0.16`），
根因在跨布局的状态泛化（200 个布局太少），**不在规划算法**。
修的顺序应该是先扩布局多样性、再改状态头结构，最后才是调规划器。

## 5. 为什么不用现成仿真器

MuJoCo / Isaac Sim / SAPIEN / Habitat 都能做交互场景，而且物理更真。本项目仍然自带一个
简化的 numpy 物理 + 软件光栅化渲染器，理由是：

1. **确定性可复现**：同一 seed + 同一动作序列 → 逐比特一致的轨迹。反事实对照（前缀必须
   逐像素相同）依赖这个性质，浮点并行物理反而容易破坏它。
2. **GT 是精确值而不是标注**：每个像素的语义 id、相机空间深度、每个方块的可见比例，
   都是渲染器直接算出来的，不需要任何标注或近似。
3. **CI 上能跑**：无编译依赖、无 GPU、无资产下载，`pip install numpy torch` 就能复现全部结果。
4. **遮挡可量化**：`render()` 会额外渲一遍"去掉遮挡墙"的场景，两次语义图的像素计数比
   就是每块物体的**可见比例** —— 这是物体持久性评测需要的量，现成仿真器并不直接给。

代价是物理简化了。这个取舍写在明面上，不藏着。

## 6. 开发过程中修掉的真 bug

这三条都是**先跑出错误结果、再定位到根因**的，留在这里因为它们比结果本身更有参考价值。

### 6.1 推的方向反了（最严重）

`_disc_box_overlap` 返回的"推出方向"原本是从方块指向执行器的方向，而调用方直接
`box += dir * depth`，于是**方块被推向执行器**。表现是：接触时方块左右乱跳而不前进，
脚本专家成功率恒为 **0/24**。

阴险的地方在于方块 x/y **都有微小位移**，看起来"像是在动"，于是很容易误判成
"策略参数没调好"。我确实在策略上白调了好几轮（改增益、改绕行、改步长），
直到写了一个**最小可复现实验**（一个方块 + 从下方推 + 打印每一步位移）才定位到。

**教训**：物理量的方向约定必须在最小实验里先把正负验清楚，再往上搭策略。
`tests/test_env.py::test_push_direction_four_faces` 现在锁死这条。

### 6.2 退化分支挑错了轴

修完方向之后仍有问题：执行器**恰好贴在方块某个面上**时（圆心到 AABB 距离 `d == 0`），
原实现走 `d < 1e-9` 的兜底分支，用 x 偏移随便挑了一个轴 —— 于是"从下方推"变成了
"方块朝 -x 走"。

**修法**：不再有"随便挑一个轴"的兜底，改成按**面法向**分四种情况判定
（内部 / 角点区 / x 外侧 / y 外侧）。见 `tests/test_env.py::test_push_direction_from_touching_face`。

### 6.3 脚本规划器的两帧极限环

绕行判定（线段是否穿过方块膨胀包围盒）在临界位置会**逐帧翻转**，导致执行器在两个格子
之间无限来回，跑满整个 horizon 一步都没推进。

**修法**：路线在**规划时一次定死**（`route = [detour?, back, stage]`），之后只按序推进；
推段用 `pushing` 状态**锁定**；只有方块移动超过 `replan_tol` 才重新规划。
见 `tests/test_data.py::test_planner_stateful_no_limit_cycle`。

## 7. 目录结构

```
wm/
  env/
    physics.py     确定性准静态推动物理：接触、分离迭代、掉桌事件
    renderer.py    numpy 软件光栅化：RGB / 深度 / 语义 / 点云，z-buffer 真遮挡
    world.py       环境封装：多模态观测、语言指令、完整 GT、反事实快照
  data/
    collector.py   三类策略采集 + 反事实配对分支 + 分片落盘
    dataset.py     定长窗口切分、语义 one-hot、反事实集加载
  models/
    world_model.py VAE/VQ 编码器 + 动作条件 Transformer/GRU 动力学 + 多任务头
  bench/
    metrics.py     八大评测维度
    planning.py    潜空间 CEM 规划（闭环 MPC）与基线
    run_benchmark.py 评测主程序 + rollout 对照图
  train.py         训练（含消融开关）
scripts/           数据采集、渲染自检、物理自检
tests/             单元测试（环境 / 数据 / 模型 / 评测）
docs/              design.md 设计说明、benchmark.md 结果
```

## 8. 相关工作（仅作定位，不是复现对象）

- **Dreamer / DreamerV3** —— 在潜空间里学习动力学并做 imagination-based planning。
- **TD-MPC / TD-MPC2** —— 用学到的潜动力学做模型预测控制。
- **MuZero** —— 学 latent dynamics + 价值，不重建观测。
- **V-JEPA** —— 在表示空间做预测，不做像素重建。
- **Genie / GAIA-1** —— 从视频里学可交互的世界模型与 latent action。
- **Diffusion Policy / ACT / VLA** —— 策略侧的相关工作。

本书目仅用于说明本项目在什么坐标系里定位；本项目**没有**复现它们的算法、数据或指标。
